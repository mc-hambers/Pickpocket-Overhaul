# 0.1.38-dev authoritative ground-reference identity

Live 0.1.35 log: drop FF000FD9 for NPC 0001A67C had expected/actual owner 00013BB9. Recovery reported exact-instance=false before starting the navigation marker walk. Later the bridge reported reached=true. This establishes that the marker path can complete, but the old instance gate can still reject pickup. It does not prove inventory pickup/equip success.

Ground recovery now validates the saved world reference ID and expected base form, rather than requiring its mutable inventory UniqueID as a prerequisite for pickup. Before each recovery pass, the exact tracked ground reference's current UID is reconciled into recovery/stolen records. If absent, the previously tracked UID is attached to that same original reference and item-extra change flags are marked. No item is spawned/copied and no other same-base world reference is selected. Inventory matching stays strict, so re-equipping cannot arbitrarily pick a duplicate in the NPC's inventory. Ground lookup no longer falls through into container inventory initialization on UID mismatch.

Existing saved drop references are eligible for reconciliation. New reconciliation logs show old/current identity. Existing diagnostics distinguish navigation, reach, actual pickup request and verified inventory recovery. Owner, combat/sleep, generated INI and timer-display behavior are unchanged. Native/Papyrus/package regression checks are automated only; actual pickup/equip remains to be verified in game.
