# 0.1.31-dev timer preview, ownership and recovery

The live report confirmed a real native armor drop from guard 00037070 to reference FF000FEF, but no subsequent pickup request. The MCM screenshot showed the timer highlighted with no preview. These observations do not establish that the previous UI/recovery implementations worked.

MCM: right-column text rows are allocated without the hidden flag. Hover updates their text to the title, formula and current-value examples; highlighting another option clears them. No dynamic SetOptionFlags reveal or hover-triggered page reset is used. Disabled rows are noninteractive. Native item recognition default remains 1.0; INI preference ownership remains unchanged.

Ownership: ExtraDataList::SetOwner in the bundled CommonLib explicitly rejects dynamic forms. A runtime-generated NPC base was therefore not a safe universal owner. Drop ownership now selects a unique static NPC base or crime faction, then a static template/base/outlaw fallback. Without a valid static owner, the original inventory transfer is retained. Ownership is assigned directly on the ground extra list and through the native setter, with the ownership change flag marked for saving. Logs show expected and actual ground owner. Existing marked recoveries with unsuitable/missing ownership are repaired when their owner and drop load nearby. A guard's own crime faction is preferred for generic guards. Ordinary vanilla faction permission/crime rules remain in force; no synthetic bounty is added. A stolen inventory tag is normally assessed upon player pickup; the ground prompt should use ownership to show Steal.

Recovery: native SKSE sends a per-NPC ModEvent after menu close. The existing PO_MCM Papyrus script now contains a minimal gameplay bridge: claim the exact native recovery request, call Actor.PathToReference, and signal completion. This is new Papyrus gameplay use, not only UI. No additional runtime script or always-running Papyrus update loop is added. Native code still selects the target, validates identity, owns pickup/equip and all persistence. Session/random request tokens reject stale callbacks; one request per NPC is active at a time. Events retry up to three times if unclaimed. A successful path is required before native nearby pickup, preventing a remote forced transfer through walls. Failed paths remain pending rather than moving the item remotely. Sleeping, clothing-in-combat, scenes, unloaded/dead owners, and taken/deleted items retain their existing safeguards. Pending recoveries persist; transient script request tokens are rebuilt after loading. Combat interrupt behavior needs runtime testing.

Public compile-only headers declare the vanilla Actor.PathToReference API, SKSE Form.RegisterForModEvent, and the dynamically named ModEvent callback for Caprica's inherited-event validation. Those reference headers are not installed to Data. Runtime package still contains only the two PO scripts, plugin, INI, DLL and licensing.

Automated checks are build, existing behavior regressions, packaging, and source contract assertions. Required live checks: hover show/hide and text clipping; original instance and Steal prompt for generic guards/unique NPCs; actual path event claim/completion; pickup and re-equip; combat/sleep/scenes; player pickup crime and no duplicate alarm; death/unload/save-load while pathing; multi-drop sequential recovery. No claim of completed gameplay verification is made.
