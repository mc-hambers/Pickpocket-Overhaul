# 0.1.28-dev equipped-item drops

Optional MCM setting "Equipped-item drops", default disabled. Toggle and pending recovery references are serialized in a separate SKSE record (PO D1 / 0x504F4431), version 1: enabled byte, count uint32, and 18 explicitly written bytes per recovery. Existing records and layouts are unchanged. No saved raw pointers.

A successful native taking attempt arms a thread-local request for the selected worn instance. Only the next matching taking transfer from the same NPC, item, ExtraDataList and game session can redirect it. The native menu's own RemoveItem virtual call is intercepted at its taking branch, after the success decision. The original source's virtual delegate is called with dropping reason, the original instance and a ground position. No copy is generated; the item never passes through the player's inventory. Quest items, ambiguous worn instances, multi-unit requests, other items, failed attempts, reverse pickpocketing and sleeping victims retain the original transfer path. Vanilla perk requirements and native crime/XP handling are not bypassed.

The audited member ABI is source in RCX, hidden ObjectRefHandle result pointer in RDX, item in R8 and count in R9, then reason/extra/destination/location/rotation on the stack. The installed executable's attempt call is RVA 0x9121FB and taking RemoveItem call is RVA 0x9123A5 (slot 0x56). Discovery starts from the existing validated attempt caller and requires one unique supported member-call signature; live bytes must match before patching. Unsupported or conflicting layouts disable this feature and its MCM toggle while retaining normal transfers. SE layouts not present locally remain unverified; do not claim universal runtime compatibility from compilation.

The native drop result is marked owned by the NPC's base, preserving vanilla ground pickup theft handling. It remains NPC-owned while on the ground, even if the original stolen-tag timer expires. Enchantment, tempering and unique instance data are passed through the original native removal. A missing returned reference is logged and never followed by a second removal. A redirected successful stack applies the existing stack penalty once, without emitting a synthetic player transfer event.

Recovery checks only marked references once per unpaused second after the container menu closes. Nearby, loaded, living owners try native pickup with clear LOS, in the same cell, within 180 units. Sleeping owners wait. Combat owners ignore clothing/armor but may recover weapons. Successful pickup is verified against the unique inventory instance on a later pass, then equipment is requested. Unloaded owners retain their records; dead owners, deleted references and items taken by another actor are abandoned. Disabling new drops does not cancel already pending recovery. Ground reference/unique-ID events update existing stolen item tracking, including recognition/tag aging after pickup.

Recovery does not add a walking/chase package or teleport distant items. If the NPC walks out of reach, pickup waits until they are close again. Native pickup/equip animation and combat handling require in-game validation. No new Papyrus gameplay script or polling loop is added; Papyrus changes are limited to the existing MCM.

Automated checks cover eligibility, reverse/failed/asleep exclusions, instance/session mismatch protection, combat recovery rules, reach/LOS, and missing/ambiguous/wrong-slot transfer signatures. The installed executable was inspected with the same discovery helper. This is executable-layout verification, not a live theft/recovery test. Live tests still required: toggle off/on, awake/asleep, equipped armor/weapon, enchanted/tempered instances, same-base duplicates, combat, player/follower pickup crime, save/load/reload/unload/death, ownership expiration, and compatibility with inventory/restoration mods.
